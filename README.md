## 1. Цель работы

Разработка объектно-ориентированной программной системы для управления учебным процессом онлайн-школы в стандарте C++20. Проект демонстрирует применение принципов SOLID (в частности, SRP), разделение владения ресурсами, перегрузку операторов, использование дружественных функций и строгое соблюдение требований статического анализатора SonarCloud.

---

## 2. Предметная область (Вариант 13)

Онлайн-школа предоставляет образовательные курсы, состоящие из модулей и конкретных занятий (лекции, лабораторные работы, практические занятия). 
* У каждого курса есть пул преподавателей и прикрепленные учебные группы.
* Контролируется предельная вместимость групп (`maxCapacity`), предотвращается дублирование записей.
* Студенты могут обучаться на нескольких курсах одновременно и выполнять задания.
* Ведется учет успеваемости: фиксируются оценки по датам, рассчитывается средний балл и отслеживается сдача контрольных нормативов.

## 3. Структура проекта

Файлы распределены по папкам `Header files/` и `Source files/`:

* **Люди и субъекты:**
  * `person.h` / `person.cpp` — базовый класс `Person` (ФИО, виртуальный вывод).
  * `student.h` / `student.cpp` — класс `Student` (ID, задачи, операторы, friend-инспекция).
  * `teacher.h` / `teacher.cpp` — класс `Teacher` (ID, кафедра).

* **Учебная структура:**
  * `faculty.h` / `faculty.cpp` — класс `Faculty` (владелец памяти `std::unique_ptr`, фабрика объектов).
  * `studyGroup.h` / `studyGroup.cpp` — класс `StudyGroup` (контроль лимита, операторы `+=` и `-=`).
  * `course.h` / `course.cpp` — класс `Course` (пул преподавателей, активности групп, профили).

* **Активности дисциплины:**
  * `courseActivity.h` / `courseActivity.cpp` — базовый полиморфный класс занятия.
  * `lectureActivity.h` / `lectureActivity.cpp` — лекции (темы, часы).
  * `labActivity.h` / `labActivity.cpp` — лабораторные работы (план, журнал оценок).
  * `practiceActivity.h` / `practiceActivity.cpp` — практика (контрольные, задачи, журнал).

* **Оценки и журналы:**
  * `date.h` / `date.cpp` — класс `Date` (день, месяц, год, операторы `==` и `<<`).
  * `grade.h` / `grade.cpp` — базовый класс оценки (балл 1–10, дата).
  * `labGrade.h` / `labGrade.cpp` — оценка за лабораторную (номер работы).
  * `practiceGrade.h` / `practiceGrade.cpp` — оценка за практику (номер и тип работы).
  * `studentContainers.h` / `studentContainers.cpp` — локальные контейнеры оценок студентов.

* **Интерфейс и обработка ошибок:**
  * `exceptions.h` — иерархия доменных исключений (`AppException`).
  * `menu.h` / `menu.cpp` — модульное консольное меню управления.
  * `main.cpp` — точка входа и демонстрационные данные.

## 4. Основной функционал

1. **Сравнение объектов:**
   * Реализован `operator==` для идентификации сущностей по уникальным ID.
   * Реализован оператор трехстороннего сравнения `operator<=>` (C++20 spaceship) в классе `Student`, автоматически генерирующий операции `<`, `<=`, `>`, `>=` по числу выполненных задач.
   * Класс `Date` использует сравнение по умолчанию (`= default`).

2. **Потоковый ввод и вывод:**
   * Перегружены операторы `<<` и `>>` для форматированного ввода/вывода данных студентов, оценок и дат.
   * Операторы оформлены по идиоме *Hidden Friend* внутри тел классов для корректного поиска ADL.

3. **Управление составом и контроль лимитов:**
   * Перегрузка `+=` и `-=` в `StudyGroup` для зачисления и отчисления студентов с проверкой `maxCapacity`.
   * Перегрузка `+=` и `-=` в `Course` для добавления и исключения преподавателей из пула дисциплины.
   * Выброс типизированных исключений (`CapacityExceededException`, `DuplicateEntityException`, `EntityNotFoundException`) при нарушении бизнес-правил.

4. **Журнал оценок и принцип SRP:**
   * Лекции не содержат оценок. Журналы объявлены только в лабораторных и практических занятиях.
   * Оценки хранятся по значению (без указателей), поддерживается удаление по дате и расчет средней оценки.
   * Вывод журнала отделен от логики классов через дружественные функции (`printLabJournal`, `printPracticeJournal`).

5. **Дружественные функции:**
   * Функция `inspectStudentInternals` демонстрирует прямой доступ к закрытым полям `Student`.

## 5. Качество кода и стандарты

* **Стандарт C++20:** применение `<=>`, `std::format`, `std::span`, `using enum`.
* **Чистая архитектура:** переменные-члены строго инкапсулированы (`private`), устранены повторы имен классов в полях (`id`, `title`, `number`).
* **Без лишних зависимостей:** все операции поиска, фильтрации и проверки коллекций реализованы вручную без подключения библиотеки `<algorithm>`.
* **Чистый код:** отсутствие глубокой вложенности условий (guard clauses, C++17 `if with initializer`), разбиение меню на небольшие функции с низкой когнитивной сложностью под требования SonarCloud.
